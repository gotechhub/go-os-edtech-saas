# Experience and design

Use for V3 UI flows and design-system implementation.

1. Read `design/README.md`, `role-flows.md`, `21st-brief.md` and the relevant product module doc. Start from user task, data and error states, not an old V1/V2 screenshot.
2. Use 21st.dev for direction/catalog research where access exists, then review license, dependencies, responsiveness, keyboard/screen reader, contrast and performance before adapting components. Do not publish Respongo assets or send customer data to 21st without explicit user instruction.
3. Use readable sans-serif typography, one semantic token contract across web/native, distinct light/dark and tenant brands, lucid icons, purposeful motion and reduced-motion behavior.
4. Check learner, admin, instructor, line manager, customer Control Center and internal HQ tasks on desktop/tablet/mobile. A role preview never grants access.
5. Verify responsive widths, empty/loading/error/offline states and a real task test before marking UI accepted.
6. Default to Turkish and support English plus eight licensed add-on locales. Design HQ Language Control and customer Language Marketplace/Labels Studio as separate workflows; stress-test long tenant labels, Arabic RTL, CJK fonts and mobile preview before declaring a language ready.
